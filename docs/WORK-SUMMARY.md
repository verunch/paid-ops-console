# Paid — описание проделанной работы

Концепт внутренней консоли платёжных операций «Paid». В проекте есть живой MVP (одна интерактивная страница), статичные макеты всех состояний для импорта в Figma и общая дизайн-система.

Проект делался под русскоязычного заказчика, поэтому основной язык интерфейса и полной документации русский. MVP локализован (RU / EN), ключевые макеты есть на английском.

- Репозиторий: `github.com/verunch/paid-ops-console`
- Локально: `python3 -m http.server 4173 --directory site` → http://localhost:4173/ (стартовая страница кейса), MVP — http://localhost:4173/mvp/
- Английская версия MVP: http://localhost:4173/mvp/?lang=en
- Ключевые экраны на английском: http://localhost:4173/en/
- Сборка: `node tools/build-site.mjs` (генерирует `site/` и `site-figma-export/`)
- Схемы ИА и флоу в Miro: https://miro.com/app/board/uXjVHMdVl74=/?moveToWidget=3458764689133524864

## 2. Как сгруппированы экраны

### 2.1 Принцип группировки

1. **Сначала основа, потом новое.** Номера 1–19 — исходный набор, 20–102 — NEW, 103–116 — ключевые экраны на английском. Внутри каждого блока сначала идут обложка/галерея и дизайн-система, потом экраны.
2. **Рабочее место → экран → состояние.** Это совпадает с папками: `new/<рабочее место>/<экран>/<состояние>/`.
3. **Состояния по сценарию.** Сначала пустая форма (`default`), затем то, что видит пользователь дальше: результаты, валидация, загрузка, пустая выдача, детали, уведомление.
4. **Подстраницы сразу за родителем.** «Добавить пользователя» (`users-new`) идёт после «Пользователей», «Создать массовые выплаты» (`mass-payouts-new`) — после «Массовых выплат».

### 2.2 Имена файлов

```
site-figma-export/<путь папки>/<NNN>-<путь папки через дефис>.html
admin/basic/default/004-admin-basic-default.html
new/support/tx-edit/found/074-new-support-tx-edit-found.html
```

Номер трёхзначный: файлы сортируются правильно в Finder и в импортёре. Имя повторяет папку, поэтому один и тот же `default` не путается между экранами.

Состав и порядок полей не перерабатывались: они взяты из спецификации и сгруппированы так же, как в исходном интерфейсе. Группы: «Поиск по данным операции», «…банковской карты», «…плательщика», «…по дате», «Поиск мошеннической операции». Спецификации:

## 3. Локализация

- Русский — исходный язык и ключ перевода (подход gettext): названия полей одновременно служат ключами данных, поэтому фильтры, валидация и экспорт не зависят от языка.
- Английский подставляется на выводе: `src/console/i18n.js` переводит готовую разметку (тексты, `placeholder`, `aria-label`, `title`, тултипы), значения полей и `data-*` не трогает.
- Словарь — `src/console/en.js`: около 450 строк и шаблоны для фраз с переменными («Оплата заказа №4521», «1–10 из 16», «Правило R-315 активно», суммы `12 480,00 BYN` → `12,480.00 BYN`).
- Язык выбирается переключателем RU / EN, запоминается в браузере и передаётся ссылкой `?lang=en`; `<html lang>` меняется вместе с ним.
- Чтобы добавить язык: новый словарь по образцу `en.js` и код языка в `LANGS`.

## 4. Ключевые правила интерфейса

- **Тултипы** одинаковы для Клиента и Админа:
  - у полей «Последние 4 цифры карты», «Маска карты» и «Временная зона» тултип показывается всегда;
  - у остальных полей — только когда поле заполнено, и в тултипе **имя поля**;
  - у обрезанной ячейки таблицы — полный текст.
- **«Тестовые транзакции»**: если чекбокс отмечен, видны только тестовые операции, а кнопка экспорта скрыта.
- **Роли**:
  - Клиент не видит процессор, мерчанта, хэш карты, фрод-маркер и признак теста;
  - IP и e-mail у Клиента замаскированы.
- **Доступность**:
  - навигация с клавиатуры, фокус-кольца;
  - ловушка фокуса в drawer, Esc закрывает;
  - aria-live для уведомлений;
  - контраст WCAG AA;
  - статус всегда передаётся текстом/иконкой, а не только цветом.
